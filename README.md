# -
Этот проект содержит в себе информацию о книгах и пользователях(клиентах).

Библиотека

 Структура репозитория

| Папка - Содержимое |
| `doc/` - постановка проекта, ER-диаграмма, аналитические вопросы, журнал расследования |
| `sql/` - скрипты создания структуры БД и загрузки данных |
| `data/` - исходные данные (csv) |
| `excel/` - аудит и итоги анализа (xlsx) |
| `presentation/` - итоговая презентация |

 Структура базы данных

База: SQLite, файл `library_database.sql`. 8 таблиц, данные нормализованы:
авторы и жанры вынесены в справочники, связи с книгами — в таблицы
`book_authors` и `book_genres`.

| Таблица - Описание - Ключ - Строк |
| `book_list` - книги: название, год издания, доступность - `book_id` - 1000 |
| `authors` - справочник авторов - `author_id` - 100 |
| `genres` - справочник жанров - `genre_id` - 10 |
| `book_authors` - авторы книги, связь «многие ко многим» - `book_id, author_id` - 1185 |
| `book_genres` - жанры книги; `is_primary`: 1 — основной жанр - `book_id, genre_id` - 1467 |
| `clients` - читатели: имя, фамилия, телефон, возрастная группа, дата регистрации - `client_id` - 500 |
| `loans` - выдачи: даты, статус, просрочка - `loan_id` - 2000 |
| `book_ratings` - оценки книг читателями (0–10), `UNIQUE (client_id, book_id)` - `rating_id` - 1443 |

Представления: `client_rating` — рейтинг читателей, `book_rating` — рейтинг книг.
`loans.status` — вычисляемый столбец: «на руках», если нет даты возврата,
иначе «возвращена».

  Качество данных (итоги расследования)

Проверено 19 гипотез, полный журнал — в `doc/`.

Главная проблема — выдачи без связей. В исходном файле почти все 2000
выдач ссылались на несуществующих читателей и книги: корректных строк было
только 13. Идентификаторы приведены к существующим по правилу остатка
от деления; исходные значения сохранены в таблице импорта.

Исправлена доступность книг: в исходнике все книги были отмечены
как доступные, хотя 67 из них фактически на руках — им поставлено
`is_available = 0`.

Что в порядке: пропусков и дублей в книгах и читателях нет; даты,
просрочки и оценки в допустимых границах; все 1443 оценки совпадают
с возвратами книг (оценку без выдачи поставить нельзя).

Оставлено как есть: пустая дата возврата у 68 выдач со статусом
«на руках» и нулевая просрочка у 1753 — это осмысленные значения,
а не пропуски.

 Аналитические вопросы

1. Кому выдать карту лояльности, а кому нет?
Критерии: срок регистрации больше 3 месяцев, число взятых книг,
дни просрочки. Книги не выдавать читателям с рейтингом ниже 5.

2. Что списать, а что докупить?
Докупить: книги, которые дольше всего на руках и чаще всего берут
с просрочкой (высокий спрос). Списать: непопулярные книги со старым
годом издания.

 Как запустить

1. Выполнить скрипт `sql/library_database.sql` — создаст структуру и загрузит данные.
2. Данные для проверки — в `data/` и `excel/`.
3. Рейтинги доступны как представления `client_rating` и `book_rating`.
